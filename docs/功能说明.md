# Octopus 功能说明

Octopus 是一个**面向个人使用的 LLM API 聚合服务**。它把多个大模型供应商的渠道聚合到统一入口，支持 OpenAI Chat / OpenAI Responses / Anthropic 三种协议之间的互相转换，并提供 Web 管理面板用于渠道管理、会话绑定、价格维护与用量统计。

---

## 核心概念

- **渠道（Channel）**：连接某个 LLM 供应商的基础配置单元，包含类型、Base URL、密钥、代理等。
- **会话（Session）**：一次客户端对话的标识。每个新会话都需要人工选定一次上游渠道和模型。
- **API Key**：提供给客户端（OpenAI SDK / Claude Code / Codex）的访问密钥，格式为 `sk-octopus-…`。
- **绑定（Bind）**：为某个会话指定实际请求的渠道与模型；选路完全由会话绑定决定，与请求中的 `model` 参数无关。

---

## 一、LLM 转发与协议转换

- **统一转发入口**（`POST /v1/*`），按请求路径区分三种协议：
  - `/v1/chat/completions` → OpenAI Chat 格式
  - `/v1/responses` → OpenAI Responses 格式
  - `/v1/messages` → Anthropic 格式
  - 另有 `GET /v1/models` 暴露可用模型列表。
- **协议互转**：在三种 API 格式之间做流式/非流式的双向转换，供不同客户端接入已经很成熟（适配模块源自 `looplj/axonhub`）。
- **多渠道聚合**：一个入口对接任意数量、任意供应商的渠道（OpenAI、Anthropic、Gemini 等）。

### 请求头处理

- **同协议直通**：客户端协议与渠道协议一致时，客户端请求头**原样转发**给上游，依赖客户端身份校验的中转服务可正常使用。
- **跨协议转换**：自动剔除不属于目标协议的客户端专属头（如转发到 OpenAI 渠道时的 `anthropic-*`），避免上游报错。
- 渠道可配置**不转发的请求头**（逗号分隔），用于补充自动规则覆盖不到的情况。

---

## 二、会话管理（人工选路）

这是本项目最具特色的机制——**不使用自动负载均衡，而是由用户为每个会话手动选择渠道和模型**：

- **会话识别**：优先使用客户端携带的会话标识（Claude Code、Codex 等）；没有时由系统提示 + 首条用户消息派生出稳定标识。
- **请求中的 `model` 参数不参与选路**，仅作日志展示；实际使用的渠道/模型在日志页为会话选定。
- **新会话等待**：新会话的请求会一直等待，直到在日志页完成选择；等待超过约 60 秒请求失败，但待选状态保留约 5 分钟，此时完成选择后客户端重试即可立即命中。
- **失败不自动切换**：已绑定渠道失败时按全局转发配置重试**同一**渠道，耗尽后请求失败并保留绑定，等待用户手动更换。
- **内存态**：会话与绑定保存在内存中，进程重启后需重新选择；进程内最多保留约 20 个会话。
- **实时通知**：新会话进入等待时可通过浏览器通知提醒（设置页开关）。

## 三、渠道管理

管理面板「渠道」页支持：

- 渠道的**增删改、启用/停用**。
- **模型同步（fetch-model / sync）**：自动从上游拉取可用模型列表；查看上次同步时间。
- **代理支持**：每个渠道可独立配置是否走系统代理或自定义代理。
- **Base URL 自动补全**：按渠道类型自动补全 API 路径——
  - OpenAI Chat → `/chat/completions`
  - OpenAI Responses → `/responses`
  - Anthropic → `/messages`
  - Gemini → `/models/:model:generateContent`
- 渠道请求头如上所述的三种处理策略。

---

## 四、价格与模型管理

- **价格数据来源**：
  - 系统定期从 [models.dev](https://github.com/sst/models.dev) 同步模型价格。
  - 创建渠道时，若渠道含不在 models.dev 的模型，会自动在此页创建该模型的价格记录，便于手动设价。
  - 也支持手动创建自定义模型及价格。
- **价格优先级**：本页面手动设置的价格（高）> models.dev 自动同步的默认价格（低）。覆盖默认价只需在此页设置自定义价即可。
- **价格重建**：`rebuild-price` 重建价格；`update-price` 单条更新。

---

## 五、日志页（请求状态实时回溯）

实时日志通过 SSE（`/api/v1/log/overview/stream`）逐条推送请求状态，支持：

- 查看请求的**完整生命周期**：`running → committed → success / failed / canceled`。
- 查看**每一轮尝试**（RoundRecord）：命中渠道、模型、耗时、失败原因，用于回溯重试过程。
- **按需查看请求/响应原文**：请求体、响应体通过独立接口按需拉取（避免大体积入状态流）。
- **人工中止**（interrupt round）：中止正在进行的某一轮上游请求。
- **清空日志**。

---

## 六、用量统计

- 统计维度：**今日 / 每日 / 每小时 / 累计**，并按 **渠道 / 模型 / API Key** 分别统计请求数、Token 消耗、费用。
- **批量写库策略**：统计数据先存内存，再按设置页的「统计保存周期」定期批量写入数据库，降低读写开销。
  - ⚠️ 退出要用正常方式（`Ctrl+C` / `SIGTERM`），**勿用 `kill -9`**，否则内存态统计可能丢失。

---

## 七、API Key 管理

- 为客户端生成、管理多个 **API Key**（`sk-octopus-…`）。
- 每个 Key 的增删改与独立用量统计。
- `/v1/*` 转发入口通过 **API Key 鉴权**保护（middleware `APIKeyAuth`）。

---

## 八、转发配置（全局参数）

设置页可配置全局重试与超时：

| 配置项 | 说明 | 默认 |
|--------|------|------|
| 单渠道总尝试次数 | 包含首次请求；耗尽后失败并保留绑定 | `2` |
| 重试间隔（秒） | 同渠道相邻两次尝试的等待 | `3` |
| 非流式响应超时（秒） | 等待完整非流式响应 | `120` |
| 流式首帧超时（秒） | 等待首个有效流事件；首帧后不再受限 | `30` |

> 超时以明确的超时原因失败，而非挂到客户端自行放弃。

---

## 九、用户与鉴权

- 唯一管理员账户，默认 `admin` / `admin`（首次登录请立即修改）。
- **登录**（签发会话 token）、**修改用户名 / 密码**、查询**登录状态**。
- 管理 API 由 `Auth` 中间件保护；转发 API 由 `APIKeyAuth` 保护。

---

## 十、数据备份 / 恢复

- **导出（backup）**：将渠道、模型价格、API Key、设置，以及（可选）全部统计表导出为 JSON。
- **导入（restore）**：采用**增量语义**（新行插入、带自然键的表 upsert），避免覆盖已有数据。

---

## 十一、版本自更新

- 检查 **GitHub Release** 最新版本与当前版本对比。
- **在线更新**：拉取最新 Release 压缩包并解压替换自身（直连失败时自动回退到系统代理）。
- 可用环境变量 `OCTOPUS_GITHUB_PAT` 提供 GitHub Token，规避版本检查的速率限制。

---

## 十二、系统与部署

- **多数据库**：SQLite、MySQL、PostgreSQL 三种后端，建表/迁移自动执行（含版本化迁移）。
- **配置文件**：`data/config.json`，首次启动自动生成；所有项可用环境变量 `OCTOPUS_*` 覆盖。
- **优雅关闭**：注册退出钩子，写回内存态统计数据、关闭数据库。
- **前端**：Next.js 构建产物嵌入 Go 二进制，单文件分发；管理面板含首页/渠道/模型/日志/API Key/设置/登录等页面，支持桌面与移动端、中英繁多语言。

---

## 十三、支持的客户端接入

| 客户端 | 接入方式 |
|--------|----------|
| OpenAI SDK | `base_url=http://127.0.0.1:8080/v1` + `api_key=sk-octopus-…`，`model` 填任意值 |
| Claude Code | `~/.claude/settings.json` 设置 `ANTHROPIC_BASE_URL`、`ANTHROPIC_AUTH_TOKEN` 及模型映射 |
| Codex | `~/.codex/config.toml` 配置 `model_provider`、`wire_api = "responses"`、`base_url` 等 |
